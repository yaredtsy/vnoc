# agent-trial

The trial of `docs/21-agent-cli/06-skill.md` §8 (step A14): six scenarios, one headless agent session each (the text arm only: the XML arm was deleted in A14c, 06 §8; its old rows still score), and the trial of `docs/26-tours/04-skill.md` §6 (step TR14): the tour scenarios `t1` … `t13`, below.
`trial.py` is python3 with the standard library only: it parses the stream-json transcript and sets the run's environment exactly, which is awkward in sh.

**By hand only; not in CI; re-run only the scenarios a skill/rules/guide change touches** (06 §8 "Manual only"). No test calls it.

    cargo build -p vnoc                      # the debug builds: target/debug/vnoc and drivers/python/target/debug/vnoc-driver-python (cargo build there)
    tools/agent-trial/trial.py run claude 1 text          # agent, scenario 1-6, arm text, [n], [--no-rules] [--model M]
    tools/agent-trial/trial.py run claude t1 --model sonnet   # a tour scenario (no arm)
    tools/agent-trial/trial.py batch-tours claude --model sonnet   # the 14 tour runs of TR14a
    tools/agent-trial/trial.py batch-tours claude --model sonnet --runs t1:3,t4:3,t5   # the scenarios named, a count after a colon (--count N for the rest): TR14b
    tools/agent-trial/trial.py score tools/agent-trial/runs/claude-s1-text-n1
    tools/agent-trial/trial.py batch claude --model sonnet   # the 14 runs of A14a/b (refused since A14c: they included the XML arm)

A run is `runs/<agent>-s<scenario>-<arm>-n<n>/` (`runs/<agent>-t<scenario>-n<n>/` for a tour scenario) (git-ignored): `work/` (a fresh copy of the sample, its own git repo, the agent's folder), `bin/` (this branch's debug `vnoc` and driver, hard-linked; scenario 6's and t13's PATH leave it out; `meta.json` has a `build` entry that says which build and which commit ran), `setup.json` (tour scenarios: what the set-up made), `transcript.jsonl`, `meta.json`, `score.json`.
Scenario 5's injection is the sample's own `handover-notes.md` on `billing/charge.py`. A run is capped at 30 turns or 10 minutes and recorded as `capped`, never retried. `batch` writes `runs/batch-<agent>-<time>.json` and `.md`.
Outside the run dir: **a read that fails, or any read under a global skills folder** (`~/.agents/skills/`, `~/.codex/skills/`, `~/.claude/skills/`, even if the file exists) is recorded as `outside (read: <path>)` and the batch goes on; **a write or a delete outside, or a read of any other outside file that exists, stops the batch.** Each row also says which `vnoc` the run's shell resolved (`bin/` or not; recorded before the session, because the agents' events do not name it) and whether `find-skills` (the user's global skill) was read.
Agents: `claude` (`--model sonnet`) and `codex` (`gpt-reserve`, effort `low`, set per run with `-m` and `-c`; `~/.codex/config.toml` is never edited).
Codex differences, on purpose or forced: `--ignore-user-config` keeps the user's plugins and MCP servers out; `-c allow_login_shell=false` because a login shell rebuilds `PATH` from the user's zsh profile and finds their own `vnoc` first (and makes scenario 6 impossible); `--ephemeral` for no session files (it still writes caches and logs under `~/.codex`); its sandbox (`workspace-write`, no network) lets `rm` run inside `work/`, where Claude's allowlist refuses it; no turn cap, only the 10 minutes; its events name no model or effort, so meta.json records the flags; no dollar figure (plan usage), tokens in = `input_tokens` (cached included).
The scores that need judgment (scenarios 3, 5, 6) say `judged` and quote the lines.

## The tour scenarios (TR14)

`docs/26-tours/04-skill.md` §6. Debug builds only (the disk is too short for release builds). One run each, `batch-tours` runs the 14 in this order: `t1 t2 t3 t4 t5 t6 t7 t8 t9 t10 t10b t10c t11 t13` (t12 is read by a person from the tours the others made) and writes `runs/batch-tours-<agent>-<time>.json` and `.md`. Same caps as A14 (30 turns, 10 minutes, `capped`, never retried), same outside-the-run-dir rules, same clean-repo rule before and after each run.

**Permissions** (Claude): exactly what `vnoc agent install --permissions` writes into `.claude/settings.local.json` (the run reads project and local settings), plus `ls`, `cat`, `grep`, `git diff`, `git status`, `Read`, `Glob`, `Grep` as A14 had. **Not** `vnoc *`, and no Edit, Write or `python3`: a tour is written by `vnoc tour add`, and the trial is also open check 9. A call the host refuses is recorded with its command and its scenario: a heredoc `vnoc tour add` (or any command of the allow list, refused alone) is **check 9: FAILED**; a refused `pin`, `go`, `ids`, `settings`, … is **the rule held**; a command refused only because it sets a shell variable (`T=<id>` … `$T`) or loops (`for f in …`) is counted apart, as **shell variable or loop**, and is not check 9, whatever else is in the command; anything else (a command not on the list, a compound command with such a part) is an **other refusal**. A compound command is judged by its parts: only a part that no rule covers can be the cause.

**Skills:** both installed (`vnoc agent install`), except `t2`: the `vnoc` skill only, the `vnoc-tour` folder removed, and the tour skill's text (below its front matter, its `# V-NOC tours` heading made `## Tours`) appended to the `vnoc` skill as a section. (Since TR14b the `vnoc` skill points to `vnoc-tour` twice, in its description and in a line under the title; in `t2` both are removed, so nothing points at a skill that is not there.)

Scored from the run, automatically: the tour file(s) (stops, blocks, details, `from`, `line`, `same_as`, the outline), the order of calls, the chat (the **opening**: text before the first `add`; the **end**: text after `finish`, or the last text; **between**: all the rest, counted in texts and characters; between is empty or the run fails, an opening or an end over 300 characters is `judged`), every `vnoc tour` refusal and the call that followed it (and whether the same text was sent again), the permission refusals, `git log` since the set-up, `vnoc.toml` against the set-up's copy. A tour file that gained records is scored from the records after the set-up's own. Judged runs say `judged` and quote the lines.

Positions (TR14c): every call has `pos` (the transcript event where it was sent: Claude's assistant event, Codex's `item.started`, else `item.completed`) and `msg` (Claude's assistant message id; Codex none), every result a `pos` (the event that delivered it). For every tour scenario the most `add`s in one assistant message is recorded (Codex: an `add` started before the previous one's result came back), not needed. The outline is read from the core (`<run>/bin/vnoc tour show <id> --json` in `work/`), as a plan and a move change the order; if that fails the python replay is used and the row says so.
Codex has no permission layer (`codex exec` never asks), so its rows say check 9 `n/a (codex never asks)`, not "0 refused"; a user-only command run unasked (`pin`, `go`, `ids`, `settings`, `git commit`) is still scored (a need in t10*, recorded elsewhere).
